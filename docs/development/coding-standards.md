# Coding standards

- Use TypeScript for application code and keep process boundaries explicit.
- Use ESLint for code quality and Prettier for formatting; add their configurations with the Phase 1 application toolchain.
- Use EditorConfig for consistent whitespace and line endings.
- Prefer small, focused changes and descriptive names.
- Validate untrusted input at process and IPC boundaries.
- Add unit, integration, or end-to-end coverage with the feature being implemented.
- Document decisions that affect process boundaries, security, or contributor workflow.

The application-specific rules and commands will be finalized when its toolchain is initialized.
